# مدل داده

## Article

ریشه دامنه مقاله؛ وضعیت جاری و اشاره به محتوای نسخه فعلی را نگه می‌دارد.

| فیلد | نوع مفهومی | قاعده |
|---|---|---|
| id | شناسه | یکتا و تولیدشده توسط سامانه |
| slug | رشته | یکتا؛ حروف کوچک، فاصله به خط تیره، حفظ حروف فارسی و پسوند عددی در برخورد |
| title | رشته | الزامی و غیرخالی |
| excerpt | رشته | الزامی و غیرخالی؛ نام ثابت فیلد خلاصه |
| bodyMarkdown | متن | الزامی |
| tags | فهرست رشته | مقدار ساختاریافته؛ از ورودی معتبر ساخته می‌شود |
| status | enum | یکی از وضعیت‌های جدول زیر |
| currentVersion | عدد صحیح مثبت | با هر تغییر محتوایی افزایش می‌یابد |
| createdAt / updatedAt | زمان | زمان ایجاد و آخرین تغییر |
| publishedAt | زمان تهی‌پذیر | فقط هنگام انتشار؛ در لغو انتشار تهی می‌شود |

مقاله به چند `ArticleRevision`، چند `ReviewReport` و چند `AgentRun` مرتبط است. منبع نمایش عمومی فقط Article با وضعیت PUBLISHED است. مقاله منتشرشده قبل از ویرایش باید لغو انتشار شود.

## ArticleRevision

Snapshot تغییرناپذیر از محتوای مقاله در یک نسخه.

| فیلد | نوع مفهومی | قاعده |
|---|---|---|
| id | شناسه | یکتا |
| articleId | شناسه مقاله | مرجع به Article |
| version | عدد صحیح مثبت | در هر مقاله یکتا و افزایشی |
| title, excerpt, bodyMarkdown, tags | snapshot | محتوای کامل همان نسخه |
| createdAt | زمان | زمان ثبت نسخه |
| changeSource | enum | تولید، ویرایش دستی یا اصلاح با ایجنت |

نسخه اول با تولید معتبر نویسنده ساخته می‌شود. هر ویرایش محتوایی فقط یک نسخه تازه می‌سازد؛ شکست عملیات ایجنت نباید نسخه ایجاد کند.

## ReviewReport

گزارش محتوایی بازبین که به snapshot مشخص متصل است.

| فیلد | نوع مفهومی | قاعده |
|---|---|---|
| id | شناسه | یکتا |
| articleId | شناسه مقاله | مرجع به مقاله |
| reviewedVersion | عدد صحیح مثبت | نسخه snapshot بررسی‌شده |
| verdict | enum | APPROVED یا NEEDS_CHANGES |
| score | عدد صحیح | ۰ تا ۱۰۰ |
| strengths | فهرست رشته | نکات مثبت ساختاریافته |
| findings | فهرست Finding | هر یافته دارای severity، location، issue و suggestion |
| createdAt | زمان | زمان تکمیل گزارش معتبر |

گزارش موفق باید کامل و معتبر باشد. گزارش نسخه قدیمی برای انتشار نسخه فعلی اعتبار ندارد. خطای بازبینی گزارش موفق نمی‌سازد و وضعیت/متن مقاله را حفظ می‌کند.

## AgentRun

سابقه فنی هر اجرای ایجنت؛ از ReviewReport جداست.

| فیلد | نوع مفهومی | قاعده |
|---|---|---|
| id | شناسه | یکتا |
| agentType | enum | WRITER یا REVIEWER |
| articleId | شناسه تهی‌پذیر | برای تولید اولیه ممکن است هنوز مقاله‌ای وجود نداشته باشد |
| inputVersion | عدد صحیح تهی‌پذیر | نسخه ورودی؛ برای تولید اولیه تهی |
| modelName | رشته | نام مدل انتخاب‌شده، بدون راز اتصال |
| outcome | enum | SUCCESS یا FAILURE |
| durationMs | عدد صحیح نامنفی | زمان اجرای اندازه‌گیری‌شده |
| createdAt | زمان | زمان اجرا |

کلید API، توکن، prompt حساس و stack trace در این موجودیت ذخیره نمی‌شوند.

## Finding و تنظیمات

`Finding` مقدار توکار گزارش است: severity در HIGH/MEDIUM/LOW، و فیلدهای الزامی location، issue و suggestion.

تنظیمات Writer و Reviewer جداگانه از متغیرهای محیطی خوانده می‌شوند: endpoint، model، API key و timeout. کلیدها فقط در adapter همان ایجنت مصرف می‌شوند و در پایگاه داده/پاسخ API ثبت نمی‌شوند. System prompt و نسخه آن برای هر ایجنت جدا نگه‌داری می‌شوند.

## وضعیت و گذارها

| وضعیت مبدأ | رویداد | وضعیت مقصد | قید |
|---|---|---|---|
| — | تولید موفق | DRAFT | خروجی نویسنده معتبر؛ نسخه ۱ |
| DRAFT | درخواست بازبینی | IN_REVIEW | snapshot نسخه فعلی ثبت شود |
| NEEDS_CHANGES | درخواست بازبینی دوباره | IN_REVIEW | snapshot نسخه فعلی ثبت شود |
| IN_REVIEW | گزارش APPROVED معتبر | APPROVED | گزارش متصل به نسخه ورودی |
| IN_REVIEW | گزارش NEEDS_CHANGES معتبر | NEEDS_CHANGES | گزارش متصل به نسخه ورودی |
| IN_REVIEW | خطای ایجنت | وضعیت قبلی | متن و مجوز انتشار حفظ شوند |
| NEEDS_CHANGES | ویرایش یا اصلاح صریح | DRAFT | نسخه جدید؛ تأیید قبلی نامعتبر |
| APPROVED | ویرایش | DRAFT | نسخه جدید؛ تأیید قبلی نامعتبر |
| APPROVED | انتشار دستی | PUBLISHED | گزارش APPROVED برای نسخه فعلی لازم است |
| PUBLISHED | لغو انتشار دستی | APPROVED | حذف فوری از نمای عمومی |

هر گذار دیگر با تعارض وضعیت رد می‌شود (`409`).
