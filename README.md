# وبلاگ با ایجنت‌های نویسنده و بازبین

مستندات و برنامهٔ طراحی یک وبلاگ مبتنی بر API که در آن ایجنت نویسنده پیش‌نویس مقاله را تولید می‌کند و ایجنت بازبین نسخه‌ای مشخص از آن را ارزیابی می‌کند. انتشار مقاله فقط پس از تأیید بازبین و اقدام صریح مدیر انجام می‌شود.

## وضعیت فعلی

مرحلهٔ نیازمندی‌ها و طراحی انجام شده است: PRD بررسی شده و اسناد مشخصات، برنامه و وظایف آماده‌اند. **پیاده‌سازی برنامه هنوز آغاز نشده است**؛ بنابراین فرمان‌های اجرا و APIهای این README هدف طراحی هستند و در حال حاضر تضمین نمی‌شود که قابل اجرا باشند.

## آنچه تا اینجا انجام شده

- PRD پروژه در `.specify/prd/PRD.md` مبنای استخراج نیازمندی‌ها قرار گرفت.
- مشخصات قابلیت در [`spec.md`](specs/001-ai-blog-agents/spec.md) تهیه شد؛ شامل داستان‌های کاربری، الزامات عملکردی، معیارهای پذیرش و محدودیت‌های امنیتی.
- برنامهٔ فنی در [`plan.md`](specs/001-ai-blog-agents/plan.md) تدوین شد؛ معماری، فناوری‌های پیشنهادی، مدل داده و مسیر راه‌اندازی را مشخص می‌کند.
- اسناد پشتیبان برنامه آماده شدند: [`research.md`](specs/001-ai-blog-agents/research.md)، [`data-model.md`](specs/001-ai-blog-agents/data-model.md)، [`quickstart.md`](specs/001-ai-blog-agents/quickstart.md) و قرارداد [`OpenAPI`](specs/001-ai-blog-agents/contracts/openapi.yaml).
- چک‌لیست نیازمندی‌ها در [`requirements-checklist.md`](specs/001-ai-blog-agents/checklists/requirements-checklist.md) قرار دارد.
- فایل [`tasks.md`](specs/001-ai-blog-agents/tasks.md) با ۶۴ وظیفهٔ مرتب‌شده برای پیاده‌سازی تولید شد.

این موارد، اسناد برنامه‌ریزی هستند؛ هنوز کد برنامه، پایگاه دادهٔ اجرایی یا تست‌های پیاده‌سازی‌شده‌ای در این مرحله ایجاد نشده‌اند.

## قابلیت‌های برنامه‌ریزی‌شده

- تولید پیش‌نویس مقاله، ویرایش آن و نگهداری نسخه‌ها.
- بازبینی یک نسخهٔ مشخص از مقاله؛ نتیجه می‌تواند تأیید یا درخواست اصلاح باشد.
- انتشار و لغو انتشار فقط با اقدام مدیر و در وضعیت مجاز.
- نمایش عمومی مقاله‌های منتشرشده و پنهان ماندن مقاله‌های منتشرنشده.
- ثبت سابقهٔ اجرای ایجنت‌ها و مدیریت تنظیمات آن‌ها.
- پشتیبانی از حالت `MOCK` برای توسعهٔ آفلاین و حالت `REAL` برای اتصال به مدل‌های سازگار با APIهای OpenAI.

ایجنت نویسنده و بازبین نقش‌های جداگانه دارند و حافظهٔ مشترک یا امکان فراخوانی مستقیم یکدیگر ندارند. خطاهای ایجنت نباید وضعیت مقاله را بی‌دلیل تغییر دهند. نسخهٔ بازبینی‌شده هنگام انتشار باید با نسخه‌ای که مدیر تأیید کرده مطابقت داشته باشد.

## فناوری‌های پیشنهادی

- Java 17 یا بالاتر و Spring Boot 3.x
- Maven، Spring Web، Spring Data JPA و Spring Security
- H2 برای توسعهٔ محلی؛ PostgreSQL به‌عنوان گزینهٔ محیط‌های دیگر
- JUnit 5، Spring Boot Test، MockMvc و ArchUnit برای آزمون‌های برنامه‌ریزی‌شده
- مستندسازی API با `springdoc-openapi`

این‌ها انتخاب‌های ثبت‌شده در طرح هستند و تا زمان پیاده‌سازی، وجود یا پیکربندی آن‌ها در مخزن تأیید نشده است.

## API در طرح فعلی

قرارداد OpenAPI مسیرهای عمومی خواندن مقاله‌ها و مسیرهای مدیریتی برای تولید، فهرست‌کردن، ویرایش، بازبینی، اصلاح و انتشار را تعریف می‌کند. مسیرهای عمومی فقط مقاله‌های منتشرشده را ارائه می‌کنند. جزئیات و ساختار درخواست‌ها در [قرارداد OpenAPI](specs/001-ai-blog-agents/contracts/openapi.yaml) آمده است.

در نظر گرفته شده است که مسیرهای مدیریتی با Bearer token محافظت شوند. توکن‌ها و کلیدهای مدل نباید در مخزن ثبت شوند یا در پاسخ‌ها و گزارش‌ها افشا شوند.

## راه‌اندازی پس از پیاده‌سازی

راهنمای [`quickstart.md`](specs/001-ai-blog-agents/quickstart.md) اجرای محلی با Maven و حالت `MOCK` را برای زمانی که کد برنامه آماده شد توضیح می‌دهد. تنظیمات پایهٔ پیش‌بینی‌شده عبارت‌اند از:

```text
ADMIN_API_TOKEN=<local-secret>
AGENT_MODE=MOCK
```

برای اتصال واقعی، تنظیمات جداگانهٔ `WRITER_*` و `REVIEWER_*` در نظر گرفته شده‌اند. مقدارهای حساس را فقط از متغیر محیطی یا مدیریت امن اسرار تأمین کنید و کلید واقعی را در README یا فایل‌های مخزن ننویسید.

## گام بعدی

پیاده‌سازی از وظایف آماده‌شده در [`tasks.md`](specs/001-ai-blog-agents/tasks.md) آغاز می‌شود. این فایل مراحل پایه، پیاده‌سازی قابلیت‌ها و آزمون‌های پذیرش را به ترتیب وابستگی فهرست می‌کند. وضعیت فعلی این وظایف در فایل با چک‌باکس‌ها مشخص می‌شود.
